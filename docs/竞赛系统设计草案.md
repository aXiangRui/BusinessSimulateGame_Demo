# 竞赛系统设计草案

> 日期：2026-07-06  
> 状态：草案阶段，待讨论  
> 目的：为甜品店增加竞赛玩法，获取稀有材料和奖励

---

## 一、系统定位

### 1.1 核心问题

当前游戏循环是"做甜品 → 等顾客买 → 攒钱 → 解锁新配方"，缺少**爆发式目标**和**成就感峰值**。

竞赛系统的定位：

> 周期性的高风险高回报事件，玩家主动选择参赛，用自己最好的产品去争取排名和稀有奖励。

### 1.2 设计原则

- **完全可选**：不参赛也能正常经营，参赛是多一种追求
- **风险收益并存**：投入材料 + 报名费 → 赢了赚翻，输了血亏
- **利用现有系统**：评分基于已有的甜度/饱腹感/口感属性，不另起炉灶
- **可扩展**：后续可以加主题赛、好友对战、赛季排名

## 二、竞赛流程

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│  公告期   │ →  │  报名期   │ →  │  提交期   │ →  │  评审期   │ →  │  发奖期   │
│ 查看主题  │    │ 交报名费  │    │ 选产品提交 │    │ 评委打分  │    │ 领取奖励  │
│ 查看奖励  │    │ 确认参赛  │    │ 消耗产品   │    │ 公布排名  │    │ 解锁新内容│
└──────────┘    └──────────┘    └──────────┘    └──────────┘    └──────────┘
   店内公告        玩家操作         玩家操作        自动结算        玩家领取
```

### 2.1 公告期（1个游戏日）

- 店内出现"竞赛公告板"（UI弹窗或NPC通知）
- 显示：主题、评审标准、奖励预览、报名截止时间
- 玩家可选择"关注"（到时提醒）

### 2.2 报名期（2个游戏日）

- 在 `CompetitionScene` 中操作
- 消耗报名费（金币）
- 可选难度档位：初级 / 中级 / 高级（报名费不同）

### 2.3 提交期（与报名期重叠）

- 从已有产品中选择一个参赛（消耗该产品）
- 也可现场制作新产品提交（跳转到 CreateScene）
- 提交后锁定，不可更改

### 2.4 评审期（1个游戏日）

- 自动评分，展示动画（评委品尝 → 打分 → 排名）
- 评分维度取决于竞赛主题

### 2.5 发奖期

- 按排名发放奖励
- 返回 GameScene 时弹出领奖窗口

## 三、竞赛类型

### 3.1 按主题分类

| 主题 | 核心评分维度 | 加权规则 |
|------|-------------|---------|
| 🍰 **经典甜品赛** | 甜度 + 口感 | 甜度 ×1.5，其他×1.0 |
| 🍞 **饱腹挑战赛** | 饱腹感 + 口感 | 饱腹感 ×2.0 |
| 🎨 **创意装饰赛** | 装饰材料种类 + 口感 | 使用≥2种装饰材料加分 |
| 🌿 **健康轻食赛** | 甜度（低分）+ 口感 | 甜度越低越好 |
| ⭐ **全能大师赛** | 三维均衡 | 三维权重相同，看总和 |
| 🔥 **主题限定赛** | 指定基类蛋糕 | 必须用指定基类，否则0分 |

### 3.2 按难度分类

| 难度 | 报名费 | 参赛门槛 | 评委严格度 | 奖励倍率 |
|------|--------|---------|-----------|---------|
| 初级 | 100 | 无 | 宽松（方差小） | ×1 |
| 中级 | 500 | 拥有 ≥5 种产品 | 正常 | ×3 |
| 高级 | 2000 | 拥有 ≥10 种产品 | 严格（方差大） | ×8 |

## 四、评分系统

### 4.1 基础分

每个参赛产品的基础得分：

```
基础分 = 甜度 × 甜度权重
       + 饱腹感 × 饱腹权重
       + 口感 × 口感权重
       + 装饰加成（每种装饰材料 +5分）
       + 等级加成（产品等级 × 10）
```

### 4.2 随机因素

引入"评委偏好"增加不确定性，防止纯数值碾压：

- 每位评委有隐藏偏好（随机 ±15% 波动）
- 3 位评委独立打分，取平均
- 高级赛事评委方差更大

```
实际得分 = 基础分 × (0.85 + rand()%31 / 100)  // 85%~115%
最终得分 = (评委1 + 评委2 + 评委3) / 3
```

### 4.3 加分项

| 条件 | 加分 |
|------|------|
| 产品使用了 ≥2 种装饰材料 | +10 |
| 产品等级 ≥5 | +15 |
| 所用基类蛋糕恰好是评委偏爱的口味 | +20（稀有触发） |
| 参赛产品与主题完美匹配 | ×1.2 总倍率 |

### 4.4 排名

1~3 名有奖励，4~6 名参与奖，7~8 名无奖励。

## 五、奖励体系

### 5.1 奖励类型

| 奖励类别 | 内容 | 稀有度 |
|----------|------|--------|
| 💰 金币 | 直接加 TotalMoney | 普通 |
| 🧈 材料 | 限定材料（不可购买，只能比赛获得） | 稀有 |
| 📜 配方 | 解锁新甜品 / 新产品槽位 | 稀有 |
| 🏆 称号 | 展示在店铺界面 | 收集品 |
| 🎭 皮肤 | 店铺外观 / 员工服装 | 极稀有 |

### 5.2 排名奖励表（示例）

| 排名 | 初级 | 中级 | 高级 |
|------|------|------|------|
| 🥇 第1名 | 200金币 + 随机装饰材料 | 800金币 + 稀有装饰材料 | 3000金币 + 限定配方 |
| 🥈 第2名 | 100金币 + 随机基类材料 | 400金币 | 1500金币 + 稀有装饰材料 |
| 🥉 第3名 | 50金币 | 200金币 | 800金币 |
| 4~6名 | 参与奖 20金币 | 参与奖 50金币 | 参与奖 200金币 |

### 5.3 限定材料

竞赛专属的稀有材料，商店买不到：

```
示例：
- "星空奶油"    — 甜度+15, 口感+10
- "金箔碎片"    — 饱腹感+5, 口感+20
- "龙息巧克力"  — 甜度+20, 饱腹感+10
- "彩虹糖霜"    — 三维各+8
```

## 六、NPC 对手系统

### 6.1 预设对手

报名后，系统自动填充其他参赛者（NPC）：

```cpp
struct Competitor
{
    std::string name;           // "甜蜜工坊" / "面包达人小王" …
    std::string avatarPath;     // 头像贴图
    int         skillLevel;     // 1~10，决定产品基础分
    int         specialty;      // 擅长方向 (甜度/饱腹/口感)
    int         productScore;   // 本次参赛产品分数（评审期计算）
};
```

### 6.2 对手池

- 固定 7 个 NPC 对手（保证 8 人竞赛）
- 每个 NPC 有固定名称、擅长方向、技能等级
- 随着玩家等级提升，对手池也会更新（更强对手加入）
- 同一竞赛中对手产品分数在一定范围内波动

## 八、竞赛日程

### 8.1 触发机制

| 方式 | 说明 |
|------|------|
| 日历触发 | 每 N 个游戏日自动开启一轮竞赛（如每 7 天） |
| 条件触发 | 玩家解锁 N 种产品后触发首场竞赛 |
| 主动报名 | 在竞赛公告板上查看并选择参赛 |

### 8.2 竞赛频率建议

- 每 7 个游戏日开启一轮（约等于每周一次）
- 两轮之间间隔至少 3 天
- 特殊节日（游戏内节日）可开启限定竞赛

## 十、待讨论议题

以下是需要在会议上确认的关键决策：

### 🔴 必须确定

1. **竞赛触发方式**：日历自动触发 vs 玩家主动报名 vs 两者结合？
2. **产品提交**：提交后产品是否消耗（从库存扣除）？
3. **参赛频率**：每几天一轮？能不能跳过？
4. **失败惩罚**：输了之后报名费全损，还是部分返还？

### 🟡 建议讨论

5. **多人对战**：纯单机 vs 异步排行榜 vs 局域网对战？
6. **赛季系统**：每月重置排名 + 赛季限定奖励？
7. **评委角色化**：有名字/性格的固定评委 vs 匿名随机评委？
8. **竞赛与顾客关系**：获奖后是否吸引更多顾客/高消费顾客？

### 🟢 远期方向

9. **好友对战**：分享产品代码，好友间互评
10. **主题赛季**：春节限定赛、夏日冰淇淋赛、万圣节恐怖甜品赛
11. **竞赛直播**：评审过程可回放、可截图分享
